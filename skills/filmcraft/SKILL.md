# Filmcraft

Start at the requested deliverable. A script request ends with recording-ready copy and an executable picture plan. A finished-film request continues through media, edit, playback and delivery. For a revision, preserve approved material and change the named passage. The creator chooses language, length, frame and voice.

## Work in passes

1. **Commission.** Write one sentence naming the viewer, their question and what they should understand, feel or do at the end. Record available footage, voice permission, desired length and format. Make reversible editorial assumptions explicit. A missing interview can become a proposed interview; a made-up quote cannot become tape.
2. **Research.** Read the underlying sources. For every consequential assertion record an ID, author, link or supplied asset, exact locator, what it supports, and its limit. Track permission to show an asset separately from permission to describe a fact. When browsing is unavailable, use supplied material and mark unresolved claims. For fiction, label invented scenes and keep a continuity sheet instead of sourcing invented dialogue.
3. **Find the story.** Write two different openings using the material: an observable action and a consequential question. Choose the one you can pay off. Name the final image now. Connect opening to ending with changes of knowledge, intention, or physical state. Use the [format guide](references/formats.md) for the requested genre and scale.
4. **Write one sequence.** Read the [script desk](references/script-desk.md). Draft what is heard beside what is seen. Each scene needs a subject, an action, and something different by the cut. Quote tape verbatim with in/out points. A proposal, hypothesis or unresolved cause must sound like one in the actual recording copy and look like one on mute. Put a visible sketch or simulation label on proposed results. A note buried in the pickup list cannot repair a false impression in the film. Mark silence and unavailable shots in the editor column. Repeat for the remaining sequences.
5. **Rewrite before polishing.** Run the three editorial tests in the script desk. Fix the weakest passage and read the result aloud. If a factual line fails, narrow it or replace it with a supported observation. If a visual fails, specify a filmable action. If a beat repeats an earlier beat, cut it or give it new information. Return the revised draft.
6. **Deliver the script.** Supply a clean recording script, then an A/V table with time budget, exact spoken cue, shot or source, action and transition, on-screen words and sound. Include a compact source/rights ledger and any pickups. Label preliminary times as estimates. For a long film include the chapter map, then complete the scenes in order. An outline alone is a treatment.
7. **Produce when requested.** Build a scratch animatic and check its sound-off and audio-only versions. Follow [picture and sound](references/direction.md) and [voice and presenters](references/voice.md). Lock timings to actual performances; update cuts and captions together. For local assembly or handoff use [the production format and tools](references/production.md). For release copy use [publishing](references/posting.md).

## Small-context mode

Do one pass per response or file. Carry forward a short record containing the promise, source IDs and limits, approved wording, chapter durations, character/object continuity, unresolved pickups and next scene. Feed the next pass only this record, that scene’s evidence and its adjacent cuts. On a long film save the full script outside the prompt and assemble from the approved scene files. Never reconstruct earlier quotes from memory.

If the host has no tools, execute the writing passes in chat. Return the complete script and cue sheet and identify any work requiring footage, recording or an editor. A plan, a preview and a playable final export are distinct deliverables.
